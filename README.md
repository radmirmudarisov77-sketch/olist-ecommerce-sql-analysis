# Olist E-commerce — SQL & Data Analysis

**Исследовательский проект по аналитике бразильского маркетплейса Olist.**  
Стек: **PostgreSQL · SQL · Python · pandas · Seaborn · Matplotlib · SciPy · Plotly · Jupyter Notebook**

В проекте я исследую продажи, логистику, поведение клиентов, продавцов, товарные категории и способы оплаты. Цель — найти закономерности в данных, проверить гипотезы и предложить направления улучшения бизнеса.

**Данные:** публичный [Brazilian E-Commerce Public Dataset by Olist](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce), 9 исходных таблиц и **99 441 заказ** в полной выгрузке. Основной период EDA: **январь 2017 — август 2018**.

## Основные результаты EDA

| Направление | Что показали данные |
|---|---|
| **Продажи** | Выручка (сумма платежей) увеличивалась в 2017 году; спад летом 2018 года в исследованной выборке связан прежде всего со снижением числа заказов при сравнительно стабильном среднем чеке (~R$ 160). |
| **Доставка и отзывы** | Около **8,1%** доставленных заказов приходят позже обещанного срока. Средняя оценка у доставленных вовремя — **4,29**, с опозданием — **2,57**. Это связь в наблюдаемых данных, не доказательство причинного эффекта. |
| **Клиенты** | В среднем **1,03 заказа на клиента**; около **3%** клиентов совершили повторную покупку в доступном периоде. |
| **Продавцы** | **18% продавцов** формируют около **80% выручки от товаров** — заметная концентрация у крупнейших участников. |
| **Товарные категории** | **24,3% категорий** обеспечивают **80% выручки от товаров**. Категории отличаются по объёму продаж и средней цене позиции. |
| **Платежи** | На кредитные карты приходится примерно **78,5% суммы платёжных записей**. Среди оплат кредитной картой около **66,8%** предусматривают больше одного взноса. |

## Задачи исследования

1. Оценить динамику продаж: месячные суммы платежей, количество заказов и средний чек (**AOV**).
2. Изучить логистику: сроки, опоздания, различия между штатами и связь задержек с оценками.
3. Оценить повторные покупки и удержание клиентов через `customer_unique_id` и когортный анализ.
4. Выявить концентрацию выручки среди продавцов и товарных категорий.
5. Исследовать способы оплаты, популярность рассрочек и связь суммы платежа с количеством взносов.

## Данные и принципы расчёта

**Основная выборка:** заказы, приобретённые с 1 января 2017 до 1 сентября 2018 года. Крайние месяцы исходной выгрузки исключены из основного анализа из-за неполного покрытия. Для большинства метрик продаж и доставки используются доставленные заказы с заполненной датой получения.

**Важно различать денежные показатели:**

| Показатель | Расчёт | Особенность |
|---|---|---|
| Выручка от товаров | `SUM(order_items.price)` | Не включает стоимость доставки; применяется при анализе продавцов и категорий |
| Общая сумма платежей | `SUM(order_payments.payment_value)` | Может включать доставку и другие компоненты заказа; используется в динамике денежных поступлений |
| AOV | Общая сумма платежей / число заказов | Считается на уровне заказа после агрегации нескольких платежей |
| Сумма карточного платежа | `payment_value` при `payment_type = 'credit_card'` | Анализируется вместе с количеством взносов; не обязательно равна полной стоимости заказа |

**Клиент:** `customer_unique_id`, а не `customer_id`, поскольку последний создаётся на уровне заказа.  
**Корреляции:** коэффициент Спирмена описывает монотонную связь между показателями и не доказывает причинность.

### Аудит и очистка

Перед анализом выполнен аудит пропусков, дублей и аномальных дат. SQL-представления вынесены в [`sql/05_clean_views.sql`](sql/05_clean_views.sql):

| View | Назначение |
|---|---|
| `orders_period` | Заказы в выбранном периоде |
| `orders_delivered` | Доставленные заказы с датой получения и флагом `carrier_date_invalid` |
| `order_reviews_clean` | Один, последний по времени ответа отзыв на заказ |
| `products_clean` | Английские названия категорий; отсутствие категории обозначается `unknown` |

Основные особенности качества данных:

| Проблема | Обработка |
|---|---|
| Неполные крайние месяцы | Ограничение основного периода январём 2017 — августом 2018 |
| 8 доставленных заказов без даты получения | Не используются в метриках доставки |
| 166 записей с передачей перевозчику раньше покупки | Подозрительная дата помечается флагом; другие поля заказа сохраняются |
| 547 заказов с несколькими отзывами | Используется последний отзыв через `order_reviews_clean` |
| 768 заказов без отзыва | Не исключаются из показателей продаж |
| 775 заказов без товарных позиций | Не добавляют товарную выручку |
| 610 товаров без категории | Категория `unknown` |
| 2 товара без веса | Не влияют на расчёты, не использующие вес |

В [`sql/03_contraints.sql`](sql/03_contraints.sql) дополнительно задаются ключи, внешние ключи и индексы, приводятся пустые категории к `NULL` и добавляются недостающие переводы категорий. Исходная схема поэтому не полностью неизменна: этот скрипт выполняет небольшие исправления справочников.

## Как воспроизвести анализ

1. Установить PostgreSQL и создать базу `olist`.
2. Скачать публичный датасет Olist, разместить CSV-файлы в локальной папке. Сами CSV **не хранятся в репозитории** (папка `data/` указана в `.gitignore`).
3. В `sql/02_load_data.sql` изменить переменную `d` на абсолютный путь к папке с CSV. **Загрузка использует команды `\copy`, поэтому её нужно запускать через `psql`**, а не как обычный SQL в DBeaver.
4. Выполнить скрипты в порядке:

   ```text
   01_create_table.sql → 02_load_data.sql → 03_contraints.sql
   → 04_data_audit.sql → 05_clean_views.sql
   ```

5. Установить библиотеки для Jupyter, например:

   ```bash
   pip install jupyter pandas numpy matplotlib seaborn scipy sqlalchemy psycopg2-binary plotly nbformat
   ```

   Для экспорта изображений Plotly в PNG дополнительно требуется `kaleido`.

6. В обоих ноутбуках настроить `create_engine(...)` под локальную PostgreSQL; открыть проект из папки `notebooks/` и выполнить ячейки по порядку. Сохранение изображений через `../images/` рассчитано на запуск с этой рабочей директорией.

**Примечание:** локальная база данных и окружение не публикуются. В папке `images/` находятся сохранённые визуализации исследования.

## Ограничения анализа

- Период наблюдения ограничен: часть покупателей могла совершить повторную покупку позже, за пределами выгрузки. Поэтому доля повторных покупок не равна полному пожизненному retention.
- Условия рассрочки (проценты, комиссии) неизвестны. `payment_installments` — количество взносов, а не число строк отдельных ежемесячных платежей.
- Корреляция количества взносов со **средней суммой по каждому числу взносов** не равна корреляции на уровне отдельных платёжных записей.
- Таблица `geolocation` не используется в JOIN: один почтовый индекс может иметь несколько координат, что создаёт риск дублирования строк.
- Данные не содержат затрат и маржи, поэтому по ним нельзя оценить прибыльность маркетплейса.

## Стратегические альтернативы

По результатам EDA предложены четыре направления для дальнейшей проверки:

- **Удержание клиентов:** программа лояльности с бонусами за повторную покупку и персонализированные CRM-кампании.
- **Своевременность доставки:** SLA, бонусы за соблюдение сроков и санкции за систематические нарушения со стороны ответственных участников.
- **Региональная логистика:** анализ причин задержек по этапам доставки и адресное улучшение проблемных маршрутов и регионов.
- **Развитие продавцов:** стартовые бонусы и промопродвижение новых продавцов; контроль концентрации оборота с помощью HHI.

**Подробные гипотезы, метрики и ограничения:** [STRATEGY.md](STRATEGY.md). Без данных о комиссиях, затратах и марже оценить окупаемость этих мер нельзя.
